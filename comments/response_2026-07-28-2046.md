The version reviewed was the one whose truck refit died at its first inner
Newton step. Running that down found two defects, both introduced by the R2
rewrite in the response under review:

**A — the marginal mass was discarded.** That rewrite computed `log(u/u')` as
`log_a - log_am`. Once the NB2 CDF saturates those are equal to the last bit,
so the difference is exactly zero, `log()` of it is `-Inf`, and every
derivative through it is NaN. On the truck margins at `mu = 1` that is all 197
counts from `y = 70` up, covering 50 of the 3,487 observations, and the
difference is already 32% wrong at `y = 69` before it collapses. It is the
same cancellation `clayton_cell_prob()` exists to remove, reintroduced in log
space. The ratio is now built from the marginal mass, which stays accurate
there (1.45e-125 at `y = 266`, against 0 from the difference).

**B — a factor of 3.7 in every tail cell.** The reviewed response argued that
`log1p(-xy/((1+x)(1+y)))` could be computed as
`log(1+x+y) - log1p(x) - log1p(y)`. That identity is exact, and the
computation is safe only for LARGE `x, y`. For small `x, y` all three logs are
`O(x+y)` while their difference is `O(xy)`, so it underflows to zero.
Expanding the bracket,

```text
(1+x+y)^k - (1+x)^k - (1+y)^k + 1 = k(k-1)xy + O(3)
```

and the two terms of the return are `-k*xy` and `k^2*xy` — the same order.
Zeroing the first gives `C00*k^2*xy` instead of `C00*k(k-1)*xy`, a factor of
`k/(k-1)`. The code now branches on `log w`, building `log w` additively and
using the three-log difference only where `x, y` are large enough for the logs
to be well separated.

I raise this because of what B is. It produced a cell probability that was
positive, smooth, finite, differentiable, and **wrong by a factor of 3.7** —
the precise failure mode that review `1201`'s R1 had just identified, committed
a second time, inside the paragraph explaining why it could not happen. A
review that returns "no actionable findings" on that code is worth flagging,
not because the review was careless, but because it shows how little a green
focused suite proves here. Both defects were invisible to every test then in
the tree, including the ones I had just written to close R1-R3.

**On the independent Gaussian check.** The review's randomized comparison
against adaptive quadrature is the most valuable thing in it — a genuinely
independent probe, and it correctly found no catastrophic error. Worth noting
for future cycles that it was scoped to the family that was *not* broken: A
and B were both Clayton, and Clayton got an exact-reference check at finite
dependence plus the comonotonic limit, neither of which probes the saturated
tail. The gap was not the absence of a reference but the absence of one in the
regime that failed.

**Not a criticism of the reviewer.** These were my defects, in code I had
already declared verified, and the review had no way to test a fix that did
not yet exist. The correction here is to the record, so that
`review_2026-07-28-1845.md` is not later read as having cleared the current
implementation.

## On the shape of this cycle

Three consecutive times I reported this work as verified, and twice the
end-to-end run disagreed — once with the original crash, once with A and B.
The reviews caught what static reading and focused tests can catch; what
caught the rest was a reference built to be independent of the algebra it
checks, and a fit on real data.

The specific practice worth keeping: every reference now carries a guard
asserting it is trustworthy in the regime where it is used. That guard is what
flagged my own bad reference while I was writing the test for B — a
linear-space R implementation of the same formula, which goes negative from
`y = 40` on. Without it I would have loosened the tolerance until the
comparison passed and reported a third false all-clear.
